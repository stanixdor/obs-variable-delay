### New multistream dock

- Open **Docks → Dynamic Delay — Multistream** and save up to eight destinations with a name, RTMP/RTMPS server,
  and hidden stream key. Start/stop each explicitly; stop before editing/removing. Saved destinations never
  publish automatically on OBS startup.
- The plugin can publish without starting OBS's native stream. All its destinations share one Program stream,
  one delay buffer, the same quality, and the same main streaming audio track. The existing Dynamic Delay controls
  apply to that shared master. Native OBS streaming and recording keep independent delay sessions.
- A compatible native OBS stream already active at startup supplies its encoders. Otherwise all plugin
  destinations share one private H.264/AAC pair using the OBS streaming configuration. Adding a destination does
  not add another Program encoder or full delay buffer. Starting native OBS streaming later may add encoding work.
- Each destination needs additional upload bandwidth and bounded transport/muxing resources. Destinations wait
  for a safe keyframe when joining or reconnecting. A slow or failed destination does not require a new hold scene
  for the other destinations. Server/player latency remains outside the plugin's control.
- Multistream supports **one H.264 video track and one AAC audio track**, main Program, SDR NV12/I420, and
  mono/stereo audio. It does not provide per-destination bitrate, audio mixes, resolutions, or canvases. HEVC, AV1,
  Opus, HDR/10-bit, surround, Enhanced Broadcasting, and independent canvases are outside this version's scope.
  Third-party output plugins are not modified.
- RTMP/RTMPS uses a private OBS-derived librtmp transport; RTMPS verifies certificates and hostnames. FFmpeg is
  used for FLV muxing only, not for network delivery or additional encoding.

### Credentials

Destination URLs and keys are stored locally in the plugin's `multistream.json`, **without encryption**. Unix
(macOS/Linux) uses owner-only permissions (`0600`); Windows inherits the configuration directory's OS access
controls, without a private ACL installed by the plugin. Keep that directory private, especially with portable
OBS or a custom/shared configuration location. This is not a credential vault. Do not share that file, public backups containing it, or
screenshots with keys visible. The destination list hides sensitive URL paths, and the plugin does not log keys
or raw credential-bearing transport errors. RTMP is unencrypted; use RTMPS when the provider supports it.

### Installation and upgrade

Close OBS before replacing the plugin. Remove only accidental duplicate installations of this plugin.

- **macOS:** extract the recommended ZIP and copy `obs-dynamic-delay.plugin` into
  `~/Library/Application Support/obs-studio/plugins/`, replacing the old bundle. Create the directory if missing.
- **Windows, normal non-portable OBS:** extract the complete `obs-dynamic-delay` folder into
  `%PROGRAMDATA%\obs-studio\plugins\`; create this directory if absent. Verify the DLL at
  `%PROGRAMDATA%\obs-studio\plugins\obs-dynamic-delay\bin\64bit\obs-dynamic-delay.dll`.
  **Do not copy loose `bin`/`data` folders into the OBS installation directory and do not use `%APPDATA%`.**
- **Ubuntu 24.04 x86_64:** install a native OBS 32.2.x version, then install the `.deb` with
  `sudo apt install ./obs-dynamic-delay-1.2.0-x86_64-linux-gnu.deb`. The manual archive can alternatively be
  extracted under `/usr` with administrator permission.

Restart OBS, then enable **Docks → Dynamic Delay** and **Docks → Dynamic Delay — Multistream**. Existing delay
configuration is retained. See the [complete English guide](https://github.com/stanixdor/obs-variable-delay/blob/1.2.0/docs/guide.en.md) for audio routing, troubleshooting,
build dependencies, and performance details.

### Validation

- Six SDK-free regression suites pass, including production delay-session, audio FIFO, hold lifecycle, bounded
  multistream queue, and preview-priority tests. The same suites pass with ASan/UBSan.
- Seven real network cases pass on macOS arm64 normally, with ASan/UBSan, and separately with TSan: validation,
  bounded cancellation, slow-trickle deadlines, untrusted RTMPS certificate rejection, terminal-error restart,
  IPv6 loopback, and secret-safe diagnostics. Instrumentation includes the production transport and private
  librtmp/happy-eyeballs code, not external prebuilt Qt/FFmpeg libraries.
- Real OBS 32.2.2/libobs on macOS arm64, OpenGL, x264 and hardware VideoToolbox at `30000/1001` fps: two-second
  delay, hold-scene audio, three rapid cancel/rearm cycles, scene changes, return live, joining/reconnecting, and
  a deliberately suspended receiver all pass. The healthy destination and master continue; the largest observed
  slow-destination queue was 308,460 bytes, below its 8 MiB cap. This measurement is not a universal RAM guarantee.
- Eight received FLV files decode without errors, start with an IDR and their own timestamp epoch, and have
  strictly increasing DTS per track. Secondary/reconnected payload hashes match the shared reference output.
  Color/tone checks confirm non-silent hold audio; observed A/V transition offsets remain within 77 ms in these
  runs (120 ms test threshold), not a sample-exact synchronization guarantee.
- Real controller cases pass: asynchronous VideoToolbox headers, cancel while starting, two pending destinations
  sharing one master, stopping one/last target, save/reload, eight-target limit, no autostart, Unix permissions,
  and teardown on profile/collection changes. English/Spanish dock interaction smoke tests pass separately.
- Hybrid MP4 recording/pause and optional GPU-preview regressions pass. Website version/locale/download checks,
  lint, production build, canonical/hreflang/structured metadata, sitemap and both cached locale pages pass.

All publishing tests use synthetic sources and loopback receivers only: **no real channel was streamed to and
no user OBS profile was modified**. Windows/Linux validation covers native builds and SDK-free tests, not a full
hardware/live-service compatibility matrix. The additional Metal harness attempt could not initialize graphics
before the plugin tests; no new Metal end-to-end pass is claimed. RTMPS negative-certificate testing does not
certify every provider. See [reproducible test instructions](https://github.com/stanixdor/obs-variable-delay/blob/1.2.0/tests/README.md).

### Retained limitations

Video transitions remain **Cut on keyframe**, not fades. Returning live waits for the next safe keyframe.
Preparing/Filling temporarily needs compatible hold encoders. AAC splices can have a brief gap and B-frame/AAC
alignment is not sample-exact. Missing source packets may shorten effective delay to recover safe aligned A/V.
The optional preview is approximate and excludes server/CDN/player buffering.

Native delay output support remains single-video-track encoded audio/video, including normal Hybrid MP4/MOV,
RTMP, and FLV. Raw, audio-only, video-only, native OBS delay, and actual multivideo outputs are unsupported.
OBS 32.2.2's independently reproduced x264 FPS-reduction pause issue is not patched: use divisor 1 if recording
pause is required. See the [historical 1.1.2 validation](https://github.com/stanixdor/obs-variable-delay/blob/1.1.2/docs/releases/1.1.2.md#validation).

### Nuevo panel Multistream

- Abre **Paneles/Docks → Delay dinámico — Multistream** y guarda hasta ocho destinos con nombre, servidor
  RTMP/RTMPS y clave oculta. Inicia/detén cada uno expresamente; detenlo antes de editarlo/eliminarlo. Los destinos
  guardados nunca emiten automáticamente al abrir OBS.
- El plugin puede emitir sin iniciar el directo nativo de OBS. Todos sus destinos comparten un stream Program,
  un buffer de delay, la misma calidad y la misma pista principal de audio de streaming. Los controles existentes
  de Delay dinámico se aplican al maestro compartido. Streaming y grabación nativos conservan sesiones separadas.
- Si al arrancar ya hay un stream nativo compatible de OBS activo, se reutilizan sus encoders. En caso contrario,
  todos los destinos del plugin comparten una pareja privada H.264/AAC con los ajustes de streaming de OBS. Añadir
  un destino no crea otro encoder Program ni otro buffer completo. Iniciar después el streaming nativo de OBS
  puede añadir trabajo de codificación.
- Cada destino requiere más subida y recursos acotados de transporte/multiplexado. Los destinos esperan un
  keyframe seguro al entrar o reconectar. Un destino lento o fallido no exige otra escena de espera para los
  demás. La latencia de servidores y reproductores queda fuera del control del plugin.
- Multistream admite **una pista H.264 y una AAC**, Program principal, SDR NV12/I420 y audio mono/estéreo.
  No ofrece bitrate, mezcla de audio, resolución ni canvas distinto por destino. HEVC, AV1, Opus, HDR/10-bit,
  surround, Enhanced Broadcasting y canvases independientes quedan fuera del alcance de esta versión.
  No se modifican plugins de output de terceros.
- RTMP/RTMPS usa un transporte librtmp privado derivado de OBS; RTMPS verifica certificados y nombres de servidor.
  FFmpeg se usa sólo para multiplexar FLV, no para enviar por red ni añadir codificación.

### Credenciales

URLs y claves se guardan localmente en `multistream.json` del plugin, **sin cifrar**. Unix (macOS/Linux) usa permisos
sólo para el propietario (`0600`); Windows hereda los controles de acceso del sistema del directorio de
configuración, sin que el plugin instale una ACL privada. Mantén privado ese directorio, especialmente con OBS
portable o una configuración personalizada/compartida. No es un almacén de credenciales. No compartas el archivo, copias públicas que lo
incluyan ni capturas con las claves visibles. La lista oculta las rutas sensibles de URL y el plugin no registra
claves ni errores de transporte crudos que contengan credenciales. RTMP no está cifrado; usa RTMPS si el proveedor
lo admite.

### Instalación y actualización

Cierra OBS antes de sustituir el plugin. Elimina únicamente instalaciones duplicadas accidentales de este plugin.

- **macOS:** extrae el ZIP recomendado y copia `obs-dynamic-delay.plugin` en
  `~/Library/Application Support/obs-studio/plugins/`, reemplazando el bundle anterior. Crea la carpeta si falta.
- **Windows, OBS normal no portable:** extrae la carpeta completa `obs-dynamic-delay` en
  `%PROGRAMDATA%\obs-studio\plugins\`; crea la carpeta si falta. Comprueba el DLL en
  `%PROGRAMDATA%\obs-studio\plugins\obs-dynamic-delay\bin\64bit\obs-dynamic-delay.dll`.
  **No copies `bin`/`data` sueltas en la instalación de OBS ni uses `%APPDATA%`.**
- **Ubuntu 24.04 x86_64:** instala OBS 32.2.x nativo y después el `.deb` con
  `sudo apt install ./obs-dynamic-delay-1.2.0-x86_64-linux-gnu.deb`. Como alternativa, el archivo manual puede
  extraerse bajo `/usr` con permisos de administrador.

Reinicia OBS y activa **Paneles/Docks → Delay dinámico** y **Paneles/Docks → Delay dinámico — Multistream**.
Se conserva la configuración del delay. Consulta la [guía completa en español](https://github.com/stanixdor/obs-variable-delay/blob/1.2.0/docs/guide.es.md) para el routing de
audio, diagnóstico, dependencias de compilación y rendimiento.

### Validación

- Pasan las seis suites sin SDK, incluidas las de sesión de delay de producción, FIFO de audio, ciclo de espera,
  cola acotada multistream y prioridad de preview. Las mismas suites pasan con ASan/UBSan.
- Pasan siete casos de red real en macOS arm64 normales, con ASan/UBSan y por separado con TSan: validación,
  cancelación acotada, deadline con bytes lentos, rechazo de certificado RTMPS no fiable, reinicio tras error
  terminal, loopback IPv6 y diagnóstico sin claves. Se instrumenta el transporte de producción y el código
  privado librtmp/happy-eyeballs, no las bibliotecas externas Qt/FFmpeg precompiladas.
- OBS 32.2.2/libobs real en macOS arm64, OpenGL, x264 y VideoToolbox hardware a `30000/1001` fps: pasan delay de
  dos segundos, audio de espera, tres ciclos rápidos cancelar/rearmar, cambios de escena, vuelta a live,
  entrada/reconexión y receptor suspendido deliberadamente. El destino sano y el maestro continúan; la mayor
  cola lenta observada fue de 308.460 bytes, por debajo de su límite de 8 MiB. No es una garantía universal de RAM.
- Ocho FLV recibidos decodifican sin errores, empiezan en IDR con época de timestamps propia y tienen DTS
  estrictamente crecientes por pista. Los hashes de payload de destinos secundarios/reconectados coinciden con
  la referencia compartida. Los colores/tonos confirman audio de espera no silencioso; los desfases A/V observados
  quedan dentro de 77 ms en estas pruebas (umbral de 120 ms), sin garantizar sincronía exacta por muestra.
- Pasan los casos del controlador real: headers asíncronos VideoToolbox, cancelar durante arranque, dos destinos
  pendientes con un maestro, parar uno/el último, guardar/recargar, límite de ocho destinos, no autostart,
  permisos Unix y cierre al cambiar perfil/colección. Pasan por separado las pruebas de interacción del panel EN/ES.
- Pasan las regresiones de grabación/pausa Hybrid MP4 y preview GPU opcional. En la web pasan versión/idiomas/
  descargas, lint, build de producción, canonical/hreflang/datos estructurados, sitemap y ambas páginas cacheadas.

Todas las pruebas de emisión usan fuentes sintéticas y receptores loopback: **no se ha emitido a ningún canal
real ni modificado ningún perfil OBS del usuario**. La validación Windows/Linux cubre builds nativos y tests sin
SDK, no toda la matriz de hardware/proveedores. El intento adicional del harness Metal no pudo inicializar los
gráficos antes de los tests del plugin; no se afirma un nuevo PASS end-to-end de Metal. El test RTMPS de certificado
negativo no certifica todos los proveedores. Consulta las [instrucciones reproducibles](https://github.com/stanixdor/obs-variable-delay/blob/1.2.0/tests/README.md).

### Limitaciones que se mantienen

Las transiciones de vídeo siguen siendo **Cut on keyframe**, no fades. Volver a live espera el siguiente keyframe
seguro. Preparing/Filling requiere temporalmente encoders compatibles para la espera. Los empalmes AAC pueden
tener un hueco breve y la alineación B-frame/AAC no es exacta por muestra. Si faltan paquetes, la recuperación
puede acortar el delay efectivo para mantener A/V seguro y alineado. La preview opcional es aproximada y no incluye
el buffer de servidor/CDN/reproductor.

El delay en outputs nativos sigue admitiendo audio/vídeo codificado con una pista de vídeo, incluidos Hybrid
MP4/MOV, RTMP y FLV normales. No admite raw, sólo-audio, sólo-vídeo, delay nativo de OBS ni multivídeo real.
No se parchea el fallo de pausa x264 con reducción de FPS de OBS 32.2.2 reproducido independientemente: usa divisor
1 si necesitas pausar grabación. Consulta la [validación histórica 1.1.2](https://github.com/stanixdor/obs-variable-delay/blob/1.1.2/docs/releases/1.1.2.md#validación).
