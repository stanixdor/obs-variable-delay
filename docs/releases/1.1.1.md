## English

OBS Dynamic Delay 1.1.1 is the stable native release for OBS Studio 32.2.x on macOS, Windows, and Ubuntu. It allows
delay to be added, changed, canceled, or removed while streaming or recording remains active.

This release fixes OBS 32 single-video-track Hybrid MP4/MOV, RTMP, and FLV detection on all three platforms,
corrects Windows installation guidance, and adds precise auxiliary-encoder failure diagnostics.

Use the ZIP as the primary macOS download. The plugin bundle is ad-hoc signed; the PKG has no Developer ID signature
and is **not notarized by Apple**. macOS can therefore display a Gatekeeper warning or require explicit approval.
Verify the SHA-256 hash, close OBS before installation, and install only the asset downloaded from this GitHub
Release.

The Windows DLL is not Authenticode-signed. Verify the SHA-256 hash and do not install copies from third-party
mirrors.

### What is included

- Variable 1–300 second delay for active streaming and recording outputs.
- Add, cancel, rearm, and remove delay without stopping the output.
- A selected hold scene while the initial buffer is built.
- Private hold-scene audio with Scene mix, Dedicated source, Reserved OBS track, and Silence modes.
- Conservative audio preflight without changing global OBS routing.
- RAM estimation from observed or configured bitrate.
- Optional 320×180, 2 fps audience preview captured only while open.
- Independent handling of simultaneous streaming and recording.
- Compressed-packet buffering and keyframe-safe video splices.
- A 4 GiB main-buffer safety limit and 128 MiB auxiliary-preroll limit.

### Fixes in 1.1.1

- Output compatibility now uses the actual attached video encoders. OBS 32 output types can advertise multivideo
  capability even when only one video track is active.
- Normal single-video-track Hybrid MP4/MOV, RTMP, and FLV now work on macOS, Windows, and Linux.
- Actual multivideo layouts and Enhanced Broadcasting remain deliberately unsupported.
- Windows installation now uses the correct global location:
  <code>%PROGRAMDATA%\obs-studio\plugins\obs-dynamic-delay</code>.
- Live-fallback messages now identify the output type, flags, video/audio encoder counts, encoder ID, and exact
  auxiliary-capture stage.
- Encoder-provided errors are preserved, which makes hardware-encoder session or initialization failures
  distinguishable from format rejection.

### Installation and upgrade

Close OBS before installing or replacing the plugin.

**macOS — ZIP recommended**

1. Extract the ZIP.
2. Copy <code>obs-dynamic-delay.plugin</code> to
   <code>~/Library/Application Support/obs-studio/plugins/</code>, replacing the previous version.
3. Open OBS and select **Docks → Dynamic Delay**.

The alternative PKG has no Developer ID signature, is not Apple-notarized, and can trigger additional Gatekeeper
warnings.

**Windows x64**

1. Extract the complete <code>obs-dynamic-delay</code> folder into
   <code>%PROGRAMDATA%\obs-studio\plugins\</code>.
2. Confirm this exact path exists:
   <code>%PROGRAMDATA%\obs-studio\plugins\obs-dynamic-delay\bin\64bit\obs-dynamic-delay.dll</code>.
3. Open OBS and select **Docks → Dynamic Delay**.

Do not copy loose <code>bin</code> and <code>data</code> folders into the OBS application directory, and do not use
<code>%APPDATA%</code>.

**Ubuntu 24.04 x86_64**

~~~bash
sudo add-apt-repository ppa:obsproject/obs-studio
sudo apt update
sudo apt install ./obs-dynamic-delay-1.1.1-x86_64-linux-gnu.deb
~~~

The alternative archive can be installed with:

~~~bash
sudo tar -xJf obs-dynamic-delay-1.1.1-x86_64-ubuntu-gnu.tar.xz -C /usr
~~~

The Linux artifacts target native Ubuntu 24.04 x86_64. They are not Flatpak, Snap, or cross-distribution packages.

### Validation

- 26/26 packet-core cases and 9 audio-bridge scenarios pass.
- Strict warnings-as-errors builds pass on macOS arm64/x86_64, Linux x86_64, and Windows x64.
- The macOS universal bundle contains arm64 and x86_64, with 2/2 native suites passing on each architecture.
- End-to-end OBS 32.2.2 macOS arm64 validation covered recording start, cancellation during Preparing/Filling, a
  complete delay, Program scene change, preview open/close, return to live, and final recording stop.
- The resulting 174.002 s H.264 1920×1080 + AAC 48 kHz stereo recording fully decodes with no errors and zero DTS
  regressions across 10,425 video and 8,154 audio packets.
- Hold-scene audio was non-silent in both tested scenes.
- Linux was built natively against OBS 32.2.0 and Qt 6.4.2; both suites pass and <code>ldd -r</code> reports no
  missing libraries or unresolved symbols.
- OBS loads the Linux module and completes startup under Docker/Xvfb/llvmpipe. A forced-SIGINT harness shutdown
  segfaults identically with and without the plugin, so that harness does not certify clean shutdown.
- The Windows PE32+ DLL has the required eight OBS exports and resolved imports against official OBS 32.2.2 and
  Qt 6.11.1 DLLs. A complete Windows runtime test is not claimed.
- ASan, UBSan, and TSan report no findings in both pure cores.

### Deliberate limitations

- Production uses **Cut on keyframe**. Fade is disabled because a real crossfade requires permanent decoding,
  compositing, and re-encoding.
- Returning live waits for the next keyframe to keep the bitstream decodable.
- Switching audio encoders can introduce a one- or two-frame AAC gap.
- If hold audio becomes unsafe, only that audio falls back to silence; video delay continues and global routing is
  never modified automatically.
- The audience preview does not include server, CDN, or viewer-player buffering.
- Raw, audio-only, video-only, OBS native-delay, and actual multivideo/Enhanced Broadcasting outputs are not
  supported.

### Validación

- Pasan 26/26 casos del núcleo de paquetes y 9 escenarios del puente de audio.
- Pasan builds estrictos con warnings como errores en macOS arm64/x86_64, Linux x86_64 y Windows x64.
- El bundle universal macOS contiene arm64 y x86_64, con 2/2 suites nativas correctas en cada arquitectura.
- La validación end-to-end en OBS 32.2.2 macOS arm64 cubrió iniciar la grabación, cancelar durante
  Preparing/Filling, un delay completo, cambio de escena Program, abrir/cerrar la vista, volver a live y detener
  finalmente la grabación.
- La grabación resultante de 174,002 s, H.264 1920×1080 + AAC 48 kHz estéreo, se decodifica por completo sin
  errores y con cero regresiones DTS en 10.425 paquetes de vídeo y 8.154 de audio.
- El audio de la escena de espera no fue silencioso en ninguna de las dos escenas probadas.
- Linux se compiló de forma nativa contra OBS 32.2.0 y Qt 6.4.2; pasan ambas suites y <code>ldd -r</code> no
  encuentra bibliotecas ausentes ni símbolos sin resolver.
- OBS carga el módulo Linux y completa el arranque bajo Docker/Xvfb/llvmpipe. El cierre forzado por SIGINT del
  harness termina en segfault de la misma forma con y sin el plugin, así que ese harness no certifica una descarga
  limpia.
- El DLL PE32+ de Windows tiene los ocho exports OBS necesarios e imports resueltos contra los DLL oficiales de
  OBS 32.2.2 y Qt 6.11.1. No se declara una prueba runtime completa en Windows.
- ASan, UBSan y TSan no encuentran problemas en ninguno de los dos núcleos puros.

### Limitaciones deliberadas

- La producción usa **Cut on keyframe**. El fade está deshabilitado porque un crossfade real exige decodificar,
  componer y recodificar de forma permanente.
- La vuelta a live espera el siguiente keyframe para mantener el bitstream decodificable.
- Cambiar de encoder de audio puede introducir un hueco de una o dos tramas AAC.
- Si el audio de espera deja de ser seguro, sólo ese audio cae a silencio; el delay de vídeo continúa y el routing
  global nunca se modifica automáticamente.
- La vista de audiencia no incluye el buffer del servidor, CDN ni reproductor del espectador.
- No se admiten outputs raw, sólo-audio, sólo-vídeo, el delay nativo de OBS ni multivídeo/Enhanced Broadcasting
  real.
