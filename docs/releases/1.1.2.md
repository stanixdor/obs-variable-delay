### Fixes and optimizations

- **Cancel/rearm:** retired auxiliary encoders are destroyed outside the session mutex, removing a callback/teardown
  deadlock during rapid cancellation and reactivation.
- **Recording pause:** filling advances with media time, not the paused wall-clock interval. The auxiliary output
  pauses with the recording and resumes its existing buffer.
- **Reconnect:** queues and the previous A/V timestamp bridge reset before the new epoch's first packet, including
  audio-first reconnects and B-frame offsets.
- **Encoder gaps:** lost video carriers and gaps in individual audio tracks, during Filling or Delayed, trigger
  safe multi-track alignment at a complete buffered GOP. Recovery may shorten the effective delay; it does not
  recode Program or insert another hold scene. Arrival jitter without missing media does not discard content.
- **Preview:** follows the capture timestamp of the video actually emitted, not just the slider. It preserves
  required history across recording pauses and chooses streaming when both streaming and recording are present.
- **GPU work:** reuse the rendered Program texture, downscale on the GPU to 320×180, then read back at most 2 fps.
  No raw video consumer is registered, so enabling the preview alone does not force full-resolution readback,
  keep `obs_video_active` true, or block OBS video settings. Folding frees capture/GPU resources/history; hiding
  the entire dock retains low-rate history but stops repainting.
- **Auxiliary encoding:** compatible outputs share a complete video/audio encoder bundle only when
  their original encoder identities, full audio-track layout, and hold-media hub match. Matching only video is not
  enough: partial matches stay isolated. Pause follows the original encoder state already shared by fully matching
  outputs, and stopping one subscriber preserves a bundle still in use.
- **Audio memory:** explicit Silence mode does not allocate the PCM FIFO. Redundant PCM clears/copies are removed
  without modifying global OBS audio routing.

### Installation and upgrade

Close OBS before replacing the plugin. Remove accidental duplicate installations of this plugin only.

**macOS — ZIP recommended**

1. Extract the universal ZIP.
2. Copy `obs-dynamic-delay.plugin` into `~/Library/Application Support/obs-studio/plugins/`, replacing its previous
   version. Create the plugin directory if it is absent.
3. Reopen OBS and select **Docks → Dynamic Delay**.

**Windows x64 — normal, non-portable OBS**

1. Open `%PROGRAMDATA%\obs-studio\plugins\` in File Explorer; create it if absent.
2. Extract the complete `obs-dynamic-delay` folder from the ZIP there, replacing the previous plugin folder.
3. Verify `%PROGRAMDATA%\obs-studio\plugins\obs-dynamic-delay\bin\64bit\obs-dynamic-delay.dll` exists.
4. Reopen OBS and select **Docks → Dynamic Delay**.

Do not copy loose `bin` and `data` directories into OBS's installation folder and do not use `%APPDATA%` for the
plugin. If it is missing, check **Help → Log Files → View Current Log**.

**Ubuntu 24.04 x86_64**

These packages target native OBS and the **32.2.x module ABI**. They are not Flatpak, Snap, or generic packages for
other distributions. Ensure a compatible OBS 32.2.x installation before installing the plugin; verify the version
offered by the official PPA if using it.

```bash
sudo add-apt-repository ppa:obsproject/obs-studio
sudo apt update
sudo apt install ./obs-dynamic-delay-1.1.2-x86_64-linux-gnu.deb
```

Alternatively, install the manual archive:

```bash
sudo tar -xJf obs-dynamic-delay-1.1.2-x86_64-ubuntu-gnu.tar.xz -C /usr
```

Restart OBS and enable **Docks → Dynamic Delay**.

### Deliberate limitations

- Video transitions remain **Cut on keyframe**. Fades require decoding, compositing, and re-encoding and remain
  unavailable. Returning live waits for a safe keyframe.
- An auxiliary audio-encoder splice can introduce a one- or two-frame AAC gap. Unsafe hold audio falls back only
  to silence; the plugin does not rewrite global routing.
- Codec B-frame reordering and AAC packet boundaries can add a small A/V offset at a splice; the workflow is not
  sample-exact and does not decode/re-encode Program to remove it.
- Missing source packets can prevent exact configured delay; safe recovery favors decodable, aligned A/V.
- The preview is approximate, excludes server/CDN/player latency, and shows hold-scene status instead of another
  auxiliary render. Folding discards history, so reopening an already-delayed output needs new history.
- Raw, audio-only, video-only, OBS native-delay, and actual multivideo/Enhanced Broadcasting outputs remain
  unsupported. Normal single-video-track Hybrid MP4/MOV, RTMP, and FLV remain supported.

### Correcciones y optimizaciones

- **Cancelar/rearmar:** los encoders auxiliares retirados se destruyen fuera del mutex de sesión; se elimina un
  bloqueo entre callbacks y limpieza al cancelar y reactivar rápidamente.
- **Pausa de grabación:** el llenado avanza según el reloj de medios, no según el intervalo pausado de tiempo de
  pared. El output auxiliar se pausa junto a la grabación y reanuda el mismo buffer.
- **Reconexión:** se reinician colas y puente temporal A/V anterior antes del primer paquete de la nueva época,
  también si llega primero audio y si hay offsets B-frame.
- **Huecos del encoder:** la pérdida de portadores de vídeo o huecos en pistas de audio individuales durante
  Filling o Delayed provocan una realineación multipista segura en un GOP completo del buffer. Puede acortar el
  delay efectivo; no recodifica Program ni inserta otra escena de espera. El jitter de llegada sin pérdida de
  medios no descarta contenido.
- **Preview:** sigue el timestamp de captura del vídeo realmente emitido, no sólo el slider. Conserva el historial
  necesario durante las pausas y sigue el streaming cuando coexiste con la grabación.
- **Trabajo GPU:** reutiliza la textura Program renderizada, reduce a 320×180 en la GPU y después lee a RAM como
  máximo a 2 fps. No registra un consumidor de vídeo raw: activar sólo la preview no fuerza lecturas a resolución
  completa, no mantiene `obs_video_active` activo ni bloquea los ajustes de vídeo. Plegar libera captura/recursos
  GPU/historial; ocultar todo el panel mantiene el historial de baja frecuencia, pero no lo repinta.
- **Codificación auxiliar:** los outputs compatibles comparten el conjunto completo de
  encoders de vídeo/audio sólo si coinciden los encoders originales, todo el layout de pistas de audio y el hub de
  medios. No basta con que coincida sólo vídeo: las coincidencias parciales quedan aisladas. La pausa sigue el
  estado de encoders originales ya compartido por los outputs que coinciden por completo; detener un suscriptor
  conserva el conjunto mientras otro lo use.
- **Memoria de audio:** el modo Silence explícito no reserva la FIFO PCM. Se eliminan borrados/copias PCM
  redundantes sin modificar el routing global de OBS.

### Limitaciones deliberadas

- Las transiciones de vídeo siguen siendo **Cut on keyframe**. Los fades requieren decodificar, componer y
  recodificar y siguen sin estar disponibles. Volver a live espera un keyframe seguro.
- Un empalme del encoder de audio auxiliar puede introducir un hueco de una o dos tramas AAC. El audio de espera
  inseguro cae sólo a silencio; el plugin no reescribe el routing global.
- La reordenación B-frame del codec y los límites de los paquetes AAC pueden añadir un pequeño desfase A/V en
  el empalme; no es exacto por muestra ni decodifica/recodifica Program para eliminarlo.
- La pérdida de paquetes de origen puede impedir el delay exacto configurado; la recuperación prioriza A/V
  decodificable y alineado.
- La preview es aproximada, excluye la latencia del servidor/CDN/reproductor y muestra el estado de la escena de
  espera en lugar de otro render auxiliar. Plegarla descarta el historial: reabrir con delay ya activo necesita
  historial nuevo.
- Siguen sin admitirse outputs raw, sólo-audio, sólo-vídeo, delay nativo de OBS y multivídeo/Enhanced Broadcasting
  real. Se mantienen Hybrid MP4/MOV, RTMP y FLV normales con una sola pista de vídeo.
